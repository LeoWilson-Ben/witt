# 架构与数据边界

## 请求如何流转

1. 浏览器或 Android 通过 HTTPS 访问 Nginx。
2. Nginx 提供 `/vault/` 静态资源，将 `/vault-api/` 转发至回环地址上的 Node.js 服务。
3. 后端验证浏览器会话或设备凭据，解析用户、管理员身份和账号策略。
4. 对话绑定对应代理账号及工作目录；Codex 使用 App Server，其他代理使用 CLI 适配。
5. 代理事件经过归一化、持久化，以 SSE 等接口返回界面。
6. 生成文件经过路径及访问检查后提供下载；Artifact 使用独立预览入口。

核心入口是 `backend/server.js`，主要会话逻辑在 `backend/chat-service.js`，存储在 `backend/sqlite-store.js`。修改协议或数据模型前应运行相关回归检查。

## 客户端

Web 使用原生 HTML、CSS 和 JavaScript，支持移动和桌面布局。仓库保留了 `app.js` 与 `app-workspace-20260916-r3.js` 两个入口；修改共享协议时应核对两个入口。

Android 外壳负责 WebView、原生 API 桥、Keystore、文件下载、更新、通知和 SSH。浏览器会话使用 HttpOnly、Secure、SameSite Cookie；Android 凭据通过原生层保存。二者的登录和请求路径不能简单互换。

SSH 由 Android 原生层直接连接目标服务器，网页使用终端组件展示输入输出。保存的连接密码使用 Android Keystore 相关密钥加密。SSH 连接本身不经过 Witt 后端，也不自动成为聊天上下文。

## 会话与代理

Codex thread 与 Witt 对话建立关联，`app-server-client.js` 管理请求、通知和进程通信。模型、技能与 MCP 能力从对应账号查询，不能把其他账号的目录当作当前账号可用能力。

`provider-runtime.js` 将 Claude 和 Antigravity 的流式 CLI 输出转换为聊天事件，并保存原生会话标识。当前适配器没有实现与 Codex 完全相同的分支、压缩、审查及能力发现接口。

多个对话可以并发执行，取消、排队和追加输入必须按对话和执行轮次归属，避免串到其他任务。历史分页减少首次加载的数据量；SQLite 负责持久化，浏览器本地缓存只服务界面恢复。

## Artifact 与文件

HTML 作品通过完整快照保存并生成预览版本。增量预览只应发布结构闭合的可运行 HTML。预览在沙箱 iframe 中运行，作品不需要重复宿主的下载或源码控件。

预览入口使用短期能力令牌。持有有效预览链接的人可能在有效期内访问作品，因此预览链接同样需要保密，不能当作永久、公开的静态托管地址。

附件、生成图片和交付文件属于用户运行数据。API 层会检查用户及路径；宿主文件权限仍由运行服务的系统用户决定。

## 权限边界

`auth-service.js` 负责邀请码、设备和用户策略，`chat-access-policy.js` 刷新会话权限，`execution-policy.js` 给出 Codex 的沙箱与审批参数。

普通用户默认受限于只读或工作区写入策略；管理员可以使用完全访问模式。当前普通用户的 Codex 审批策略为 `never`，管理员为 `on-request`，这不等于“危险操作必定弹窗”。Claude 与 Antigravity 有各自的模式和执行参数，需要单独审查。

用户数据分目录和 API 认证不是容器隔离。管理员共享模型账号仍可能共享服务商额度；服务器级权限可能扩大文件及进程访问范围。多用户部署需要额外的系统隔离及配额策略。

## 数据分类

| 数据 | 存放原则 |
| --- | --- |
| 源码、示例、测试夹具 | 可进入仓库，使用虚构配置和测试数据 |
| 认证与会话数据库 | 私有运行目录，限制服务用户访问 |
| 用户附件、预览与交付文件 | 私有用户目录，按访问策略提供 |
| CLI 登录数据 | 各代理的私有配置目录，不返回原始文件 |
| 兼容令牌、开放登记管理凭据 | 权限为 `600` 的独立文件 |
| Android 签名与 SSH 私钥 | 构建机或设备的私有存储 |
| 备份 | 与源数据同等敏感，建议加密及异机保存 |

安装路径和部署前检查见[部署指南](DEPLOYMENT.md)，漏洞报告见[安全策略](../SECURITY.md)。
